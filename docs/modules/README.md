# 后端模块说明

## auth

负责注册、scrypt 密码哈希、Bearer 会话、退出、成功登录次数与最近登录时间、验证码挑战和密码重置。登录计数与会话签发在同一数据库事务内完成，数据库只保存 Token 的 HMAC 摘要。重置邮件通过 `integrations/notifications` 适配器隔离，真实服务商尚未接入。

## users

负责当前用户资料、邮箱、密码、首页导航提示状态和账户删除。导航提示状态是本人私有的服务端状态；账户删除会撤销会话、移除有效柜体成员关系并匿名化账户，同时保留业务事件与审计主体。

## cabinets

负责二维码解析、实体设备绑定、槽位初始化、列表/详情、重命名、成员移除和批量删除钥匙资料。所有业务访问都要求有效成员关系；当前产品只有单一 Admin 角色。

## keys

负责钥匙创建、编辑、删除、领取和归还。领取/归还使用数据库事务、钥匙状态条件更新、柜体版本检查、active 借用唯一索引和请求幂等记录，防止重复提交及并发双借。

当前实现完成业务状态层；真实开柜、槽位传感器确认和设备离线补偿仍必须通过 `backend/src/integrations/devices` 的 adapter 接入，路由不得直接实现硬件协议。

## records

提供按当前用户成员权限过滤的借用和活动只读查询。借用、事件和审计记录不提供修改或下载接口。

## realtime

负责已登录客户端的 WebSocket 连接、心跳、会话撤销和柜体变更通知。连接复用 Bearer 会话校验，只向当前有效柜体成员发送资源 ID、版本和变更范围，不推送钥匙、借用人或凭据明文。

业务写事务成功后才发布通知；通知用于使客户端缓存失效，REST API 仍是权威数据源。当前 Hub 保存单个 API 实例内的连接；水平扩展到多实例前，必须接入 PostgreSQL `LISTEN/NOTIFY` 或专用 Pub/Sub，并保留回前台补拉作为漏消息补偿。

## audit

所有现有写接口记录成功审计；柜体、钥匙、领取、归还等业务写操作还会在事务失败后单独写失败原因码。审计 metadata 不保存密码、Token、验证码或借用人联系方式。
