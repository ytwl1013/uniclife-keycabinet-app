# 后端模块说明

## auth

负责注册、scrypt 密码哈希、Bearer 会话、退出、成功登录次数与最近登录时间、验证码挑战和密码重置。登录计数与会话签发在同一数据库事务内完成，数据库只保存 Token 的 HMAC 摘要。重置邮件通过 `integrations/notifications` 适配器隔离，默认使用 `MAIL_*` 配置的 SMTP 发送验证码；未配置时返回 `PASSWORD_RESET_UNAVAILABLE`，仅开发预览模式可不发送邮件。

## users

负责当前用户资料、邮箱、密码、首页导航提示状态和账户删除。导航提示状态是本人私有的服务端状态；账户删除会撤销会话、移除普通管理员关系并匿名化账户，同时保留业务事件与审计主体。若账户仍是任意箱子的超级管理员，删除账户会被拒绝，必须先转让权限或删除箱子。

## cabinets

负责双类型二维码解析、新柜体与槽位初始化、一次性加入码、列表/详情、重命名、超级管理员转让、成员移除、自解绑、整箱删除和批量删除钥匙资料。同 SKU 产品初始化码可批量印刷，每次新的扫码请求创建独立柜体，创建者成为超级管理员；加入已有柜体只能使用有效成员在设置页生成的十分钟一次性二维码，加入者为普通管理员。整箱删除和批量永久删除全部钥匙资料仅允许超级管理员执行；整箱删除在事务内清理关联历史与旧审计，同时保留一条全局删除审计。

## keys

负责钥匙创建、编辑、删除、领取和归还。领取/归还使用数据库事务、钥匙状态条件更新、柜体版本检查、active 借用唯一索引和请求幂等记录，防止重复提交及并发双借。所有柜体写操作（包括钥匙、加入码与成员管理）先锁定柜体再读取/修改子资源；单把删除在同一锁内检查有效借用，即使请求未携带可选版本号也不会删除正在借用的钥匙。

当前实现完成业务状态层；真实开柜、槽位传感器确认和设备离线补偿仍必须通过 `backend/src/integrations/devices` 的 adapter 接入，路由不得直接实现硬件协议。

## records

提供按当前用户成员权限过滤的借用和活动只读查询。借用、事件和审计记录不提供修改或下载接口。

## support

负责已登录用户的产品/应用反馈、SMTP 投递和客服双向会话。初次提交在同一事务中创建反馈与首条用户消息，再把邮件投递结果更新为 `sent` 或 `failed`；后续用户/客服回复都持久化为独立消息，并更新 `waiting_for_support` 或 `waiting_for_user` 会话状态。管理端可检索全局反馈并回复，用户端只能按当前会话用户 ID 查询、已读和回复本人会话。图片附件只用于初次 SMTP 投递，数据库仅保存图片数量。

## realtime

负责已登录客户端的 WebSocket 连接、心跳、会话撤销、柜体变更通知和客服回复提醒。连接复用 Bearer 会话校验；柜体事件只发给当前有效柜体成员，客服事件只发给反馈所属用户，事件仅包含资源/反馈 ID 和时间，不推送正文、钥匙、借用人或凭据明文。

业务写事务成功后才发布通知；通知用于使客户端缓存失效，REST API 仍是权威数据源。当前 Hub 保存单个 API 实例内的连接；水平扩展到多实例前，必须接入 PostgreSQL `LISTEN/NOTIFY` 或专用 Pub/Sub，并保留回前台补拉作为漏消息补偿。

## audit

所有现有写接口记录成功审计；柜体、钥匙、领取、归还等业务写操作还会在事务失败后单独写失败原因码。审计 metadata 不保存密码、Token、验证码或借用人联系方式。
