# 前端通知与客服模块

## 范围

通知与客服目前属于前端交互原型，页面位于 Expo Router 的详情路由中，业务组件分别维护在
`frontend/src/features/notifications` 与 `frontend/src/features/support`。两个入口都只对已登录会话开放，
不直接访问数据库、设备或第三方服务。

## 通知流程

1. 首页铃铛展示当前账户的未读数量，并进入通知页。
2. 通知页把当前账户可见的箱子活动映射为通知，分为“未读”和“已读”两个标签页。
3. 用户打开一条未读通知，或选择“全部已读”后，已读状态按账户保存在本地存储中。
4. 切换账户时使用独立的已读集合，避免不同账户之间共享通知状态。

当前通知内容来自本地模拟工作区的只读活动数据；没有新增后端接口，也不会修改审计记录。生产接入时，
通知列表、未读计数和已读写操作必须通过 `frontend/src/api` 调用受认证的后端 API，后端负责校验通知归属，
且不得允许用户读取未绑定箱子的通知。

## 客服流程

1. 账户页“服务支持”分组中的“联系客服”进入聊天页面。
2. 页面展示客服欢迎语、消息气泡、输入框和发送按钮。
3. 当前版本只在页面会话内保存用户输入，用于验证交互；消息不会上传、持久化或发送给真实客服。

生产接入客服服务时，前端只能通过统一请求层发送消息。后端应校验登录状态、限制消息长度与发送频率，
处理重试和幂等，并避免在日志中记录不必要的个人信息、门禁凭据、设备密钥或完整聊天正文。

## 权限与异常边界

- 两个页面由 `(details)` 登录守卫保护；会话失效时返回登录流程。
- 通知只展示当前账户已绑定箱子的活动。
- 本地通知状态读取或写入失败时保留当前内存状态，不阻塞页面使用。
- 客服原型不声称消息已被服务端接收；接入真实 API 后必须提供发送中、失败和重试状态。
