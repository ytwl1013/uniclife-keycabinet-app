# 前端通知与客服模块

## 范围

通知页面仍属于前端交互原型，反馈问题已接入后端邮件服务。页面位于 Expo Router 的详情路由中，业务组件分别维护在
`frontend/src/features/notifications` 与 `frontend/src/features/support`。两个入口都只对已登录会话开放，
不直接访问数据库、设备或第三方服务。

## 通知流程

1. 首页铃铛展示当前账户的未读数量，并进入通知页。
2. 通知页只展示需要用户关注的异常、客服与安全消息，分为“未读”和“已读”两个标签页。
3. 用户打开一条未读通知，或选择“全部已读”后，已读状态按账户保存在本地存储中。
4. 切换账户时使用独立的已读集合，避免不同账户之间共享通知状态。

当前通知内容来自本地模拟工作区的只读活动数据，仅保留成员增删、权限变更和批量清空钥匙等高关注事件。普通借出、归还、钥匙增删改和撤销只进入活动审计，不产生通知。当前没有新增后端接口，也不会修改审计记录。生产接入时，
通知列表、未读计数和已读写操作必须通过 `frontend/src/api` 调用受认证的后端 API，后端负责校验通知归属，
且不得允许用户读取未绑定箱子的通知。客服回复、设备异常和安全风险应由专用通知数据源提供，不应重新把全量活动日志映射为通知。

## 反馈问题流程

1. 账户页“服务支持”分组中的“反馈问题”进入表单页面。
2. 表单包含称呼、反馈类型（应用问题默认/产品问题）、可选标题、必填内容和最多 5 张图片。
3. 图片在客户端转换为 JPEG，最长边优先压缩到 1600 像素；超出单张限制时再次压缩到 1200 像素，再通过统一请求层提交。
4. 后端校验登录会话、字段、图片数量和大小，通过 SMTP 将反馈发送到配置邮箱。邮件附带唯一查询编号、提交时间、用户 ID、用户名和登录邮箱，并把登录邮箱设置为 `Reply-To`。
5. SMTP 未配置或发送失败时页面明确显示失败，不会声称已收到反馈。
6. 表单页右上角的“发送记录”按钮进入历史页，展示当前账户提交过的反馈、投递状态、查询编号和时间，并支持下拉刷新。

反馈接口限制内容长度、附件体积和每小时请求频率。后端日志只记录失败上下文中的用户 ID 和反馈编号，不记录反馈正文、附件、邮箱密码、门禁凭据或设备密钥。业务数据库保存反馈文字、身份快照、图片数量和投递状态供本人历史查询，图片文件/Base64 只用于当次邮件发送且不会重复保存。通用审计日志仍只保存类型、图片数量、结果和失败码。

## 权限与异常边界

- 两个页面由 `(details)` 登录守卫保护；会话失效时返回登录流程。
- 通知只展示当前账户有权查看的高关注事件、异常和客服消息。
- 本地通知状态读取或写入失败时保留当前内存状态，不阻塞页面使用。
- 反馈页提供图片压缩、发送中、发送成功编号、失败和重试状态。
- 发送记录接口在 SQL 层按会话用户 ID 过滤；前端路由守卫不能替代后端归属校验。
