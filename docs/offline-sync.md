# 离线使用与同步规则

当前版本先保证“单人离线可继续工作”，同时避免多管理员在断网时产生无法判断的借出、归还和删除冲突。

## 当前实现范围

- 移动端按账户保存最近一次成功同步的服务端基线，以及包含本地待同步操作的工作区快照。
- 快照包含柜体、管理员、槽位、钥匙、借用、活动和反馈摘要；Token 仍由 SecureStore 保存。
- 如果当前柜体只有一个有效管理员，离线时可以修改柜体名称、钥匙名称/备注，并可以借出或归还钥匙。
- 单管理员柜体还可以把钥匙创建到空槽位；本地创建的钥匙会先使用临时 ID，联网同步成功后由服务端数据替换为正式 ID。
- 单管理员柜体可以删除没有 active loan 的单把钥匙；删除操作会保留本地活动事件，并在联网后由服务端确认永久删除。
- 单管理员柜体也可以离线清空钥匙，或删除整个柜体；两者都会先检查本地是否还有进行中的借用，并把删除命令按顺序放入 Outbox。
- 每个离线操作带有稳定 `requestId`、创建时间和操作前的柜体版本，写入本地 Outbox。
- 恢复网络后按创建顺序调用现有写接口。现有服务端幂等记录和 `expectedVersion` 检查负责防止重复提交与覆盖新数据。
- 网络错误会保留待同步操作；版本冲突、钥匙不可用和权限错误会把第一条失败操作标为 `conflict`，后续操作不会静默继续。
- 连接恢复后可以先刷新服务器版本，再重试本地冲突操作；如果资源仍然不兼容，用户可以只放弃冲突的那一条，其他待同步操作继续保留。
- 普通的柜体版本变化会由客户端自动用服务器最新版本重试；钥匙已被领取、借用已被归还、对象已删除、权限变化以及清空/删除柜体等不可安全推断的情况才会停下来让用户选择。
- 多管理员柜体离线时仍为只读。加入、移除、权限变更、删除柜体、删除钥匙、清空全部钥匙和邀请管理员必须联网。

本地快照和 Outbox 的键按用户 ID 隔离，并在退出、会话失效或删除账户时清理。快照中的 `offlineSnapshotAt` 表示最近一次从服务端完整同步的时间；本地离线修改不会把它伪装成新的服务端同步时间。用户确认丢弃冲突时，客户端会从服务端基线恢复受影响柜体，避免继续显示已放弃的本地乐观状态。

当前第一版使用现有 AsyncStorage 作为本地缓存介质，正式生产发布前应结合设备锁、数据最小化和平台安全存储策略评估借用人联系方式等敏感字段的本地保存方式。

## 借出与归还

借出和归还必须绑定具体钥匙和借用记录。归还操作关闭指定的 `loanId`，不能只把钥匙状态改成可用。单管理员用户可以在离线期间连续执行：

```text
借出 -> 归还 -> 再借出 -> 再归还
```

联网时每条操作依次重放。如果柜体版本仍然连续，全部操作会自动进入服务端的正常借用和审计历史。

多管理员柜体不会允许这类离线写操作，因此其他管理员不会看到一个允许离线借出的“假可用”状态。离线页面显示最后同步时间和共享柜体只读提示；它不把过期快照解释为当前物理状态。

## 冲突规则

可以自动合并的情况：

- 同一个 `requestId` 重复上传；
- 同一个用户在同一个柜体上的连续操作；
- 归还明确指定的既有借用记录；
- 相同借用记录的重复归还。

必须停下来人工处理的情况：

- 两个管理员同时借出同一把钥匙；
- 服务器上的柜体版本已经跳过本地操作的基线版本；
- 离线删除时柜体已新增管理员；
- 权限、超级管理员转让、账户删除等安全敏感操作；
- 软件状态与真实柜门、槽位传感器或钥匙位置不一致。

服务端现有 `requestId` 幂等记录和 `expectedVersion` 冲突响应可以直接复用。后续如果要支持多管理员并发离线，需要增加专门的批量同步接口、服务端操作结果和变更游标；在此之前不开放多管理员离线写入。

## 物理柜限制

离线记录“借出”不等于离线确认柜门已打开。当前硬件 adapter 尚未接入真实设备，因此离线模式不会尝试开柜或确认槽位传感器。需要强制修正时，应在线由有权限的管理员执行，并保留异常原因和审计记录。
