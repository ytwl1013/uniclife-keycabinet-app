# 权限说明

权限只在后端执行。前端隐藏按钮不构成授权。

## 当前角色模型

柜体成员分为 `super_admin`（超级管理员）与 `admin`（管理员）。创建柜体的账户默认成为唯一有效超级管理员；通过加入二维码新增或恢复的成员一律为管理员。数据库部分唯一索引保证同一柜体最多只有一个有效超级管理员。

两种角色都可以：

- 查看柜体、槽位、钥匙、成员、借用和活动；
- 在箱子设置页生成或撤销一次性成员加入二维码；
- 重命名柜体；
- 创建、编辑和删除钥匙；
- 领取和归还钥匙。

只有超级管理员可以移除其他管理员、把超级管理员权限原子转让给另一位有效管理员、批量永久删除柜内全部钥匙资料，以及永久删除整个箱子。普通管理员不能移除超级管理员，也不能移除其他管理员；超级管理员不能解绑自己或删除自己的成员关系，必须先转让权限，或选择永久删除整个箱子。转让后，原超级管理员立即降为管理员，目标管理员成为唯一超级管理员。

普通管理员在箱子“设置”页底部删除箱子时只会停用当前账户的成员关系，并立即从当前列表移除；柜体、其他管理员绑定、钥匙与借用历史、业务事件和审计数据均保留。超级管理员在同一位置确认删除时会硬删除柜体及其全部成员绑定、邀请、槽位、钥匙、借用和业务事件，并清理此前关联的箱子审计；系统仅保留一条 `cabinets.deleted` 全局高风险操作审计。访问任意柜体资源前，后端通过 `cabinet_memberships.active=true` 校验成员身份；列表和活动查询也在 SQL 层按成员关系过滤。

拥有任意有效超级管理员身份的账户不能直接删号，必须先逐个转让对应权限或删除相应箱子，避免产生没有超级管理员的存量箱子。

反馈提交和客服会话不依赖柜体角色，但必须登录。用户端的列表、详情、已读和回复接口都按当前会话用户 ID 校验归属，账户不能传入或覆盖目标用户 ID，也不能读取或回复其他账户的反馈。客服回复只允许持有独立 `ADMIN_API_TOKEN` 的管理服务端执行，普通用户 Token 无法访问管理接口。

## 平台管理员

Next.js 管理后台使用部署环境中配置的单一平台管理员账号，与柜体成员 `admin` 角色相互独立。平台管理员可查看全局用户、审计活动和客服反馈，可读取客服会话并代表 `UnicLife 客服` 回复；不能借此直接操作钥匙、开柜或绕过柜体成员权限。后端管理路由只接受独立的服务端 `ADMIN_API_TOKEN`，普通用户会话不能访问。

停用账户属于高风险操作：后端必须在同一事务中更新用户状态、撤销全部有效会话并写入成功审计，随后断开该用户的实时连接。管理后台隐藏或禁用按钮不构成授权。

## 共享权限码

`shared/src/schemas/permissions.ts` 保留稳定能力码，供后续组织角色扩展：

- `auth:login`
- `users:read`、`users:write`
- `cabinets:read`、`cabinets:operate`
- `keys:read`、`keys:borrow`、`keys:return`
- `records:read`、`audit:read`

`cabinets:operate`、`keys:borrow`、`keys:return` 属于高风险能力，必须保留成功/失败审计、幂等控制和明确失败原因。引入新角色时，应先更新共享权限契约、本文档和权限测试，再修改路由策略。
